# 영어 스피킹 앱 — 교안 제작 규칙

이 파일은 교안(레슨 JSON)을 만들 때 항상 따르는 규칙입니다.
정답 예시는 `samples/INT1-U03-L03.json` 입니다. 형식이 헷갈리면 항상 이 파일을 기준으로 합니다.

## 1. 프로젝트 개요

- 아이폰용 영어 스피킹 연습 앱입니다.
- 학습자: 영어를 배우는 한국인 성인 (중급).
- 목적: 미국 원어민이 실제로 쓰는 문장을 반복해서 말하며, 자연스럽게 나올 때까지 연습합니다.
- 레슨 1개 = 약 10분 = JSON 파일 1개.

## 2. 폴더 구조

```
curriculum/curriculum.csv        커리큘럼 표 (레벨, 유닛, 유닛 제목, 레슨 제목)
samples/INT1-U03-L03.json        정답 예시 레슨
lessons/<레벨코드>/U<유닛2자리>/  만든 레슨 저장 위치
  예) lessons/INT1/U01/INT1-U01-L01.json
tools/                           검사용 스크립트
```

## 3. 작업 방식 (가장 중요)

1. 한 번에 **유닛 1개만** 만듭니다. 여러 유닛을 한꺼번에 만들지 않습니다.
2. 시작 전에 `curriculum.csv`에서 해당 유닛의 레슨 목록을 찾아 먼저 보여줍니다.
3. CSV에 없는 레슨은 만들지 않습니다. CSV 내용이 이상하면(빈칸, 중복 등) 멈추고 물어봅니다.
4. 이미 있는 파일을 덮어쓰기 전에는 반드시 물어봅니다.
5. 다 만든 뒤 아래 "7. 검사"를 실행하고 결과를 표로 보고합니다.

## 4. 파일 이름과 ID 규칙

- 레벨 코드: 초급 1 = `BEG1`, 중급 1 = `INT1`, 중급 2 = `INT2`, 중급 3 = `INT3`(2026-11-21 사용자 결정). 그 밖의 레벨은 사용자에게 코드를 물어봅니다. (초급 1은 2026-11-21 사용자 결정. 초급 2~4도 BEG2~BEG4로 이어 갈 예정)
- 초급 레슨은 형식은 같게 두고, 쉬운 단어와 짧은 문장(대화문 한 줄 10단어 이하)으로 씁니다. (2026-11-21 사용자 결정)
- 고급 1 = `ADV1` (고급 2·3은 ADV2·ADV3 예정). 고급은 핵심 문장 10단어까지, 대화문 한 줄 20단어까지 씁니다. 검사 스크립트 기준(8·15단어)은 그대로 두므로 그 사이 길이는 경고로 나오며 허용입니다. 유행어 금지 예외: ADV1-U01-L01 주제어 ghost/ghosting만. (2026-11-21 사용자 결정)
- `lessonId` = `<레벨코드>-U<유닛2자리>-L<레슨2자리>` (예: `INT1-U03-L03`)
- `lessonNo` = 유닛 안에서 CSV에 적힌 순서 (1부터).
- 파일 이름 = `<lessonId>.json`
- 오디오 파일 이름 = 소문자 lessonId + 구분자 (예: `int1-u03-l03_drill_01.mp3`, 느린 버전은 `_slow` 추가).
  - 오디오 파일은 아직 없습니다. **파일 이름만 적고 실제 파일은 만들지 않습니다.**

## 5. 콘텐츠 규칙

### 공통
- 미국 영어(샌프란시스코 생활 기준), 일상 구어체.
- 화자 설정: 학습자 = `me`, 상대 = `partner`.
- 가게·병원 이름은 가상 이름을 씁니다 (예: Maple Family Clinic). 실존 상호나 실존 인물 이름은 쓰지 않습니다.
- 비속어, 은어, 유행어는 쓰지 않습니다.
- 한국어 번역은 자연스러운 구어체로 씁니다. 직역하지 않습니다.
  - 기본은 존댓말. 친구·가족처럼 실제로 반말을 쓰는 사이면 반말로 씁니다. (2026-11-17 사용자 결정)
  - 한 대화 안에서 같은 사람의 말투는 끝까지 같게 유지합니다.
- 병원·약국 레슨에 진단, 약 이름과 복용량 같은 구체적 의료 정보는 넣지 않습니다.

### keySentence (핵심 문장)
- 4~8단어. 레슨 제목 상황에서 원어민이 실제로 바로 쓰는 문장.
- 교과서식·직역식 문장 금지.
- 같은 유닛 안의 다른 레슨과 핵심 문장이 겹치지 않게 합니다.
- `stress`: 강세 받는 음절을 대문자로 표시.

### explanation (설명)
- `ko`: 3~5개 항목. 뜻, 쓰는 상황, 비슷한 표현과의 차이, 문법 포인트.
- `en`: 2~3문장의 쉬운 영어 설명.
- `enKo`: `en`의 한국어 해석.

### pronunciation (발음 팁)
- 3~4개. 강세 / 연음 / 약화 / 한국인이 어려운 소리 중에서 고릅니다.
- 한글 발음 표기는 보조로만 씁니다.

### commonMistakes (자주 하는 실수)
- 3개. 한국인이 실제로 자주 하는 직역식 실수 → 자연스러운 표현 → 짧은 이유.

### dialogue (대화문)
- 정확히 6줄. partner와 me가 번갈아 말합니다 (me는 3줄).
- 핵심 문장이 me의 줄에 1번 이상 들어가고, 그 줄에 `"hasKeySentence": true`.
- 한 줄은 15단어 이하.
- `expressionNotes`: 대화문 속 유용한 표현 2개.

### drills (반복 드릴)
- 정확히 6문장. 1번은 핵심 문장 그대로.
- 2~6번은 핵심 패턴을 유지하면서 아래 변형 중 **서로 다른 것**을 씁니다.
  - 단어 교체 (시간, 장소, 물건 등)
  - 주어 변경 / 단수·복수
  - 비교 (better / best)
  - 시제 또는 공손형 (would, will, 과거)
  - 질문형
  - 부정형
- `point`: 어떤 변형인지 짧게 적습니다.
- `cue`: 9~10회차에 앱이 던지는 상황 질문. 보통 `"lang": "en"` 질문. 드릴 문장이 질문형이면 `"lang": "ko"` 지시문.

### drillStages / retryRule
- 샘플 파일의 값을 **그대로 복사**합니다. 임의로 바꾸지 않습니다. (현재 통과 기준은 모두 80)

### rolePlay (마무리 롤플레이)
드릴 6문장을 모두 실제 대화처럼 말해 보는 단계입니다. (2026-11-20 사용자 결정)
- 12줄, partner → me를 6번. n번째 세트의 me 대답 = 드릴 n번 문장.
- me 줄은 `"freeResponse": true`, `exampleEn`·`exampleKo`는 드릴 문장의 `en`·`ko`를 **그대로** 씁니다.
- 세트마다 상황이 다릅니다. partner 한 줄만 듣고도 상황을 알 수 있게 씁니다 (누가·어디서·무엇을).
- partner 질문은 그 드릴 문장이 **가장 자연스러운 대답**이 되도록 만듭니다. 드릴 `cue`와 같은 질문은 쓰지 않습니다.
- 드릴 문장이 질문형이면, partner는 망설이거나 사정을 말해서 내가 그 질문을 되묻게 만듭니다.
- `requiredKeywords`: 세트마다 2~3개. 그 문장의 변형 포인트(시제·부정·비교 등)와 **문장 뒷부분 단어**를 넣어, 문장을 끝까지 말해야 다 맞게 합니다. 모두 `exampleEn`에 그대로 있는 말만.
- `situation`·`partnerRole`·`passRule`은 샘플 값을 그대로 씁니다.

## 6. 하지 말 것

- 샘플에 없는 항목(키)을 새로 만들거나, 있는 항목을 빼지 않습니다.
- 확인하지 않은 내용을 "확인했다"고 보고하지 않습니다.
- 사용자가 요청하지 않은 파일 삭제는 하지 않습니다.

## 7. 검사 (유닛 작업이 끝날 때마다)

처음 한 번은 `tools/check_lessons.py` 검사 스크립트를 만들어 두고, 이후에는 그 스크립트를 실행합니다.

1. 모든 JSON 파일이 문법 오류 없이 열리는지
2. 샘플과 비교해 빠진 항목(키)이 없는지
3. 대화문 6줄(me 3줄), 드릴 6개, 롤플레이 12줄(대답이 드릴 문장 순서대로)인지
4. drillStages가 샘플과 똑같은지
5. 유닛 안에서 핵심 문장·드릴 문장이 겹치지 않는지
